01 · FIRST STEPS

Start with a working network

Network Explorer is a simulated network lab. Build a topology, configure its devices, send traffic, and inspect the decisions along the path. Everything happens inside the model; the Browser application does not browse the real Internet.

  1. From Home → Example networks → Basic, open Simple LAN.
  2. Select one host. The Inspector shows its configuration; the Terminal lets you issue commands.
  3. Select the other host and note its IPv4 address. Switch back to your source host and enter ping followed by that address.
  4. Watch frames travel through the switch. Open Activity and select a row to read the frame and event details.
  5. Turn on Watch for the switch, then repeat the ping. Read each explanation and choose Continue.
Make the first exchange visible. ARP and MAC learning change what happens on subsequent attempts. Use Clear learned state before repeating a cold-start experiment.

04 · BUILDING BLOCKS

Place and configure devices

Choose a device in the palette, then click a clear spot on the canvas. Press Esc to cancel placement. Select a device to open its Inspector; drag it to reposition it.

Host

An endpoint that sends and receives traffic. Set its name, operating system, static IPv4 address and prefix, default gateway, and DNS server, or choose DHCP. Hosts can run server and browser applications.

Switch

Connects Ethernet interfaces inside a LAN. Configure its access VLANs and port state. Inspect the MAC forwarding table to see which source MAC was learned on which port.

Router

Connects IP subnets. Each routed interface has its own address and prefix. Inspect connected and static routes, ARP entries, DHCP relay settings, NAT/PAT, and optional firewall policy.

Firewall

A transparent two-port appliance with stateful filtering enabled. It bridges frames without IP addresses, routing or NAT. Configure zones, rules and sessions in the compact Firewall section.

Addressing checklist

  • Give each host a unique address in its intended subnet. The prefix determines which destinations it considers local.
  • For remote destinations, set the host gateway to the router interface on the same LAN.
  • Configure a reachable DNS server when using hostnames.
  • On routers, address both sides of the path and provide routes for the return journey.

Use the linked CIDR Teaching Tool beside host addressing when you need to work through subnet calculations. Device OS/platform selections change the terminal command vocabulary; they do not provide a complete operating system.

05 · CONNECT THE NETWORK

Cables connect interfaces

  1. Use a device’s connection anchor to start a cable. Drag to the other device’s anchor, or click the two endpoints.
  2. Choose an available Ethernet interface when the port picker appears. An In use port already belongs to a cable.
  3. Complete the other end, then check the connection and interface state.
  4. Select a cable or interface to inspect it. Enable or disable the connection/interface to experiment with link failures.

You can also drag a device onto another device to begin a connection. An anchor may be reused for several cables, but each cable needs available interfaces. Move the devices to improve wire routing.

Link up does not mean IP reachable. Link indicators show connection/activity state. A lit link can still have an incorrect VLAN, IP address, gateway, route, or missing application.

The model blocks Layer 2 loops. Build loop-free switched LANs; routed links can form different paths when their routes are configured.

07 · UNDERSTAND THE LAN

Ethernet, ARP, and VLANs

A host needs a destination MAC address before it can deliver an Ethernet frame. ARP resolves an IPv4 address to a MAC address on the local LAN. For a remote IP destination, the host resolves its gateway’s MAC.

A switch learns the source MAC on the incoming port. It forwards a known destination toward the learned port, and floods broadcasts or unknown destinations to eligible ports in the same VLAN.

Separate traffic with access VLANs

  1. Select the switch and create/name the VLANs you need.
  2. Select each interface and assign its access VLAN. VLAN 1 is the default.
  3. Send traffic between hosts in the same VLAN, then compare with hosts in different VLANs.
  4. Inspect the forwarding table and Activity VLAN column to explain the result.

Access frames are untagged. This workflow models access VLANs, not trunk links carrying tagged traffic. A router connects IP subnets; a switch alone does not route between VLANs.

Read the tables

The MAC table maps MAC addresses to switch ports and VLANs; the ARP table maps local next-hop IP addresses to MAC addresses. Table highlights help relate entries to the topology. Use Expand table to keep a table visible in a movable panel and Dock to return it. Expiration indicators help explain why an entry disappears or is relearned.

08 · CROSS A SUBNET BOUNDARY

Routing and NAT/PAT

Routers select the matching route with the longest prefix. Connected routes come from interface configuration. Static routes specify how to reach remote networks.

Configure a routed path

  1. Give each router interface an address/prefix for its attached subnet and enable it.
  2. Set each host’s default gateway to its local router interface.
  3. In the router’s routing table, choose Add static route. Enter a name, destination network, prefix, and next hop; save it.
  4. Add the corresponding return route where needed. Inspect routes and use ping/traceroute to test both directions.

At each routed hop, the Ethernet header changes and TTL decreases. The source and destination IP addresses normally remain the same; NAT is a deliberate exception. No matching route or an expired TTL can produce an ICMP error.

Share an outside address with NAT/PAT

  1. Open Internet and NAT for a configured example, or select your own router.
  2. In NAT / PAT, enable outbound NAT. Open the settings for each relevant interface and set its NAT role to Inside or Outside / WAN.
  3. Ensure addressing, gateways, and routes work on both sides. Generate client traffic toward the outside network.
  4. Inspect the NAT table and Watch explanations for the inside address, translated outside address, and port/identifier mapping.
Read both directions. Outbound translation creates runtime mappings; return traffic uses them to reach the private client. NAT/PAT changes addresses; the separate Firewall panel controls which routed conversations may pass. Inbound port forwarding is not modeled.

09 · DECIDE WHAT MAY PASS

Stateful firewall policy

Place Firewall from the device palette, or enable Firewall in an existing router’s Inspector. The dedicated device is a two-port transparent bridge with filtering enabled, Inside and Outside zones, an outbound allow rule, and default drop. Insert it inline between a switch and router, or between two hosts on the same subnet. It needs no IP address, routing table, or NAT, and preserves frame addresses and IP TTL. Existing routers retain optional routed filtering, disabled until you enable it. Older saved routed firewall devices retain their routed behavior.

  1. For a dedicated transparent firewall, connect its two bridge ports into the traffic path; leave host IP addresses and gateways unchanged. For a router with filtering enabled, address its routed interfaces and configure gateways and routes. Both directions of a conversation must cross the filtering device.
  2. Assign each interface a security zone: Inside, Outside, or DMZ. These are independent of NAT roles. A three-interface router can represent all three zones.
  3. Choose Add rule. Name it; select from/to zones, source and destination IPv4 addresses or CIDR networks, protocol, optional source/destination ports, and allow/drop. Use * for any address or port. Ports require TCP or UDP.
  4. Save the rule. New rules appear last. Use the up/down arrows to set priority; the first enabled matching rule handles a new conversation. Edit, disable, or delete a rule using its row controls.
  5. Set If no rule matches to drop or allow. A tracked reply uses the permitted session rather than needing a new reverse-direction rule.

Sessions shows permitted conversations and states; Recent decisions shows the last 12 allows/drops. Idle sessions expire after 120 seconds. TCP requires a SYN, matching SYN-ACK and ACK; FIN/ACK or a valid reset closes the session. UDP uses endpoint/port matching; ICMP echo replies must match the request identity.

Placement matters. Only traffic that crosses the device is filtered. A transparent firewall can filter same-subnet traffic when placed between the hosts. Hosts connected to the same switch on one side bypass it. A router firewall filters traffic routed between its interfaces.

Try the Firewall example

  1. Open Home → Advanced → Firewall. Open Inside Client’s Browser and browse to http://www.firewall.example/. DNS and HTTP pass, including stateful replies.
  2. From Inside Client, run ping 198.51.100.10. Default drop stops this new ICMP exchange. Watch Edge Firewall to see the rule decision; the client times out.
  3. Open Outside Services’ Browser at http://192.168.10.20/. The unsolicited inbound connection is blocked.
  4. From Inside Client, ping 192.168.10.20. This same-subnet exchange bypasses the firewall and succeeds.
  5. In Troubleshooting, choose Break something → Firewall policy. A verified fault inserts a DNS deny rule before the allows. Use Hint, Look here, Reveal fault, Check repair, and Reset network. Disable/delete the deny or move it below the matching DNS allow.

Watch the decision and NAT ordering

Enable Watch on the firewall and send traffic. Examine identifies allow/drop, the rule, security zones, protocol and session state. A dropped packet has no outgoing frame; the sender receives no explicit rejection. Activity records the decision. On routers, policy evaluates after inbound reverse NAT and route selection, before outbound NAT, so rules use the internal client address. Transparent firewalls bridge allowed frames unchanged and perform no NAT. Examine shows original and translated headers when NAT applies.

Scope of this teaching model

This is an IPv4 traffic policy model. Transparent firewalls pass ARP and DHCP unchanged, even with default drop, so discovery and address configuration work across the bridge. Router filtering excludes ARP, locally addressed traffic, and DHCP relay control traffic. It supports the simulator’s ordered TCP exchanges, UDP and ICMP echo; related ICMP errors through the firewall, TCP retransmission, host firewalls, VLAN trunks, application/content inspection, VPNs, and port forwarding are not modeled. Firewall settings are configured in the Inspector; routers retain router commands; transparent devices expose bridge-port status. Configuration edits clear learned state so the next test uses the new policy. Save/load preserves rules and zones, not live sessions, counters, or decision history.

10 · GIVE HOSTS A SERVICE

Applications and DHCP

Choose DHCP server, DNS server, Web Server, or Browser from the palette. Click a host to install it, or place it on the canvas. Select the application icon to configure it. Application icons belong to their hosts; they do not need separate Ethernet cables.

Supply client configuration with DHCP

  1. Give the server host a suitable static IP address.
  2. Install and enable the DHCP server application.
  3. Create a pool: name, start/end addresses, prefix, gateway, DNS server, and lease duration. Keep the pool appropriate for the client subnet.
  4. Set the client to DHCP and acquire a lease using its Inspector control or OS-specific renew command.
  5. Inspect the client’s assigned address, gateway, DNS settings, lease timer, and server leases.

A lease has a lifetime. Its countdown uses real time; renew it to extend the lease. Activity lets you follow discovery, offer, request, and acknowledgment.

Reach a DHCP server on another subnet

Use the DHCP relay example. Configure a helper/server address on the router interface facing the client LAN. The remote server needs a pool for that client subnet, and routers need routes in both directions. A local broadcast by itself does not cross a router.

Check configuration before connectivity. If a client cannot obtain an address, investigate the pool, application state, link/VLAN, and relay first. Do not begin by assuming DNS is the problem.

11 · FROM A NAME TO A PAGE

DNS and web browsing

Resolve a hostname

  1. Install and enable DNS on a reachable host.
  2. Add an A record containing a name, IPv4 address, and TTL; save it.
  3. Set the client’s DNS server address, directly or through DHCP.
  4. Run nslookup server.example using your actual record name. Inspect the response, cache, and Activity.

A cached answer can avoid a new lookup until it expires. Flush the client DNS cache when testing a record change or repeating a first lookup.

Serve and fetch a page

  1. Install Web Server on a host. Enable it, configure its port, title, and page body, then save.
  2. Install Browser on a client. Enter an http:// URL using the server address or configured DNS name, and choose Go.
  3. Follow DNS (if required), TCP setup, HTTP GET, and the response in Activity.
  4. Use Reload to repeat the request or Expand to enlarge the browser view.
Use the modeled web service. The server serves one small page at / and /index.html, up to 800 UTF-8 bytes. Use HTTP URLs. This is an instructional TCP/HTTP exchange, not a general web browser or full TCP performance simulator.

13 · FOLLOW THE DECISIONS

Animation, Watch, and Examine

Choose Slow, Normal, Fast, or Turbo for the animation pace. Choose Immediate to complete every exchange without packet animations or Watch pauses. All engine events are still processed: Activity, command results, learned tables, leases, caches, NAT mappings, and application results update normally. Selecting Immediate during an exchange finishes the remaining traffic immediately; Watch settings remain available when you return to an animated speed. Pause/resume lets you stop movement; Finish current exchange immediately advances the exchange without waiting through the animation.

  1. Select a device and enable its eye-shaped Watch control. Applications also provide Watch controls for their own activity.
  2. Generate traffic. A watched decision opens Examine and pauses the exchange.
  3. Read the incoming evidence, header values, tables, and explanation of the selected action.
  4. Choose Continue to proceed. Disable Watch in the dialog or on the device when you no longer want these stops.

Expand Examine when you need more room. Compare the incoming frame with the outgoing decision: flooding versus forwarding, next-hop ARP, route selection, TTL changes, or NAT translation, or firewall allow/drop.

Watch and monitoring answer different questions. Watch pauses at a decision. Activity monitoring selects which devices contribute visible capture evidence. A display filter narrows what you see; it is not a network firewall.

Simulation ticks and animation speeds are teaching aids, not measured network latency or bandwidth.

14 · READ THE EVIDENCE

Activity and traffic filters

Open Activity to inspect the exchange as a capture. Rows include event number, tick, device/port, VLAN, source/destination MAC, protocol, source/destination IP, and a short explanation.

  1. Open the eye-shaped monitor selector and choose the devices you want to observe.
  2. Enter a filter. Valid expressions apply after a short pause; correct an invalid expression using the displayed feedback.
  3. Select a row to inspect event details and the modeled Ethernet header bytes.
  4. Use the inline × to clear the filter, or Clear capture to remove recorded events.

The canvas traffic filter and monitor controls also help focus the visible exchange. Check these controls when expected traffic seems absent; it may be hidden from the view.

15 · YOUR WORKING LAYOUT

Keep the right tools together

  • Select a dock tab to switch between Terminal, Activity, and Troubleshooting.
  • Drag a tab onto a tab bar to group it, or toward a pane edge to split it into a separate column.
  • Choose Show all tools side by side to compare tools at once. Resize the dividers to change their proportions.
  • Drag the top edge of the bottom dock to change its height. Minimize it to recover canvas space.
  • Use a tool’s Expand control for a larger view. Use its docking/return controls to bring it back.
  • Expand tables independently when you want to compare learned state with a terminal command or watched packet.

For keyboard layout changes, focus a tab: Alt + arrow keys reorder, and Alt + Shift + arrow keys split. Focus a resize separator and use arrow keys for adjustments.

Try a diagnosis layout. Put Terminal beside Activity, leave the router’s table visible, and collapse the palette. Run one command, then explain its corresponding events.

16 · KEEP CONTEXT CLOSE

Notes and search

Choose Note and place it on the canvas. Select it to edit the title, text, color, and tags. Associate a note with a device or application when the explanation belongs to that item.

  • Type @ in a note to mention a device. Follow the mention to locate it.
  • Hover over a note for a preview; pin it open to keep the text visible, and drag the preview handle to move it.
  • Drag the note icon to reposition it; use Delete note in its Inspector to remove it.
  • Use tags such as #client or #walkthrough to organize related notes.

Find an item in a large network

Use Search network above the canvas. Search device names, IP addresses, operating systems, installed services, or note text. Use #tags to narrow results. Choose a match to locate the item and open its details.

The Campus network includes walkthrough notes. Read them alongside the relevant client, service, or router rather than trying to infer the whole network at once.

17 · BREAK, INVESTIGATE, REPAIR

Practice with a verified fault

The Troubleshooting tab supplies a symptom and tools to investigate it. Start with a generated practice network or a working network of your own.

  1. Open Generate practice network. Choose Basic (a switched LAN), Intermediate (2–3 routed LANs), or Advanced (3–5 LANs with chain/ring routing).
  2. Enable Start with a fault in that menu if you want a broken generated scenario immediately. Generated service faults can involve missing DNS, DHCP, or web applications.
  3. For an already working network, choose Break something: Easy disables a host interface; Intermediate changes a gateway or switch port; Hard changes a switch access VLAN; Firewall policy inserts a DNS deny rule on a working routed web/DNS path.
  4. Read the symptom and use the supplied test command or client Browser. Inspect links, configuration, tables, and Activity.
  5. Make a repair in the Inspector or Terminal, then choose Check repair.
  6. Explain the fault, the evidence, and your fix when prompted.

Hint

Receive progressively more specific diagnostic guidance.

Look here

Locate the relevant device so you can inspect it.

Reveal fault

Read the explicit fault and repair guidance.

Reset network

Restore the challenge’s saved working baseline. This also removes edits made during the challenge.

A fault needs a working baseline. Break something verifies that a test succeeds before it introduces one failure. If no eligible fault exists, choose another difficulty or generate a practice network. Hard requires another VLAN on a connected switch; custom ping challenges require suitable statically addressed hosts.

Frame / packet
A frame carries Ethernet addresses for one link. An IP packet carries the network-layer source and destination inside it.
MAC / ARP
MAC identifies an Ethernet interface. ARP discovers the MAC for a local next-hop IPv4 address.
Prefix / subnet / gateway
The prefix identifies the network portion of an IP address. A subnet groups addresses; the gateway is the local router used for remote destinations.
VLAN
A separate Layer 2 broadcast domain on a switch.
DHCP / DNS
DHCP supplies client IP configuration. DNS resolves a name to an address.
NAT / PAT
Network address translation changes addresses; port address translation distinguishes exchanges sharing an outside address.
Stateful firewall / security zone
A firewall permits or drops traffic crossing it using policy and tracked conversations. A security zone groups interfaces for policy; it is independent of NAT roles and VLANs.
TTL
For IP, the remaining hop limit. For a DNS record, how long an answer may remain cached.
