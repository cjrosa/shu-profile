How to read this demonstration

Bits are numbered 15 through 0, with bit 0 at the right. Each column adds the two operand bits and the carry entering that column. A carry beyond bit 15 is an overflow; add that 1 back to bit 0 using a separate addition. This end-around carry is what makes the addition one's-complement arithmetic.

The receiver uses the same header with the generated checksum included. A folded sum of 0xFFFF and a complement of 0x0000 pass this exercise's check. Some multiple-bit changes can cancel each other; the result comes from the arithmetic, not the error control.

TCP uses a fixed 20-byte header without options: data offset 5, reserved bits 0. Its sequence and acknowledgment numbers are split into upper and lower 16-bit words. UDP Length is an editable header value; no payload bytes participate in this exercise. Network byte order is big-endian.

The value inserted into the header is the raw 16-bit complement for this demonstration. It is not a standards-compliant TCP or UDP packet checksum; actual UDP checksum omission and zero-value transmission rules are outside this exercise.
