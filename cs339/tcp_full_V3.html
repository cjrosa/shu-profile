Phase—
Congestion control phases

Slow start: cwnd grows by one MSS for each new data ACK in this simulator, until it reaches ssthresh.

Congestion avoidance: growth slows to roughly one MSS per window of acknowledged data.

Fast recovery (Reno): after three duplicate ACKs, retransmit the missing segment and reduce the window; return to congestion avoidance when recovery completes.

A timeout returns to slow start. Tahoe also returns to slow start after three duplicate ACKs.

ssthresh—
Slow-start threshold (ssthresh)

The congestion window (cwnd) grows rapidly below this threshold, then grows more gradually in congestion avoidance. MSS means maximum segment size; 8 MSS is eight full-sized segments.

Tahoe: a timeout or three duplicate ACKs lowers ssthresh and resets cwnd to 1 MSS, restarting slow start.

Reno: a timeout also restarts slow start at 1 MSS. Three duplicate ACKs instead trigger fast recovery; cwnd settles at ssthresh when recovery ends, then congestion avoidance resumes.

ssthresh = max(floor(previous cwnd / 2), 2 MSS)

Use cwnd just before the loss, not the previous ssthresh. floor rounds down.

In this simulator: loss sets ssthresh to half the previous cwnd, rounded down, with a minimum of 2 MSS. Tahoe detects loss by timeout; Reno uses a simplified fast recovery with cwnd set directly to ssthresh.

cwnd—
Congestion window (cwnd)

A sender-side limit on how much data can be in flight without being acknowledged, used to avoid overloading the network.

This card shows cwnd in MSS (maximum segment size). For example, 4 MSS with 1,000-byte segments is 4,000 bytes.

ACKs increase cwnd rapidly during slow start and more gradually during congestion avoidance. Detected packet loss reduces it; a timeout resets it to 1 MSS in this simulator.

The effective window is min(rwnd, cwnd), with both measured in bytes. Data already in flight uses part of that window, leaving less room for new data.
