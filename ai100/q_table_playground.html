A memory for useful actions

A Q-table does not contain a route. It stores an estimate for every available state-action pair, then improves those estimates using experience.

StateWhere the agent is now.
ActionA move it can legally make.
RewardImmediate numerical feedback.

Meet the update terms

Each experience changes one estimate. These six pieces explain how far it changes and why.

old QThe estimate stored before this experience.
rewardThe immediate feedback after the action.
best next QThe most useful legal action known in the next state.
α · learning rateHow far to move toward the new target.
γ · discount factorHow strongly future usefulness matters.
new QThe revised estimate saved in the table.
New estimate = old estimate + learning rate × (reward + discounted best future estimate − old estimate)
= + × ( + × − old Q)

Agent

Environment

The grid and its rules, boundaries, rewards, and goal.

Episode

One attempt, usually ending when the goal or another terminal state is reached.

Policy

The current strategy: choose the action with the highest Q-value in each state.

Exploration

Trying an action to gather experience instead of always choosing the current favorite.

Important: a high Q-value is an estimate based on training. It is not a guaranteed reward, a fact about the world, or evidence that the agent understands the task.

Three ideas to compare
Rewards spread backward

A state becomes valuable when it leads toward another state that already has useful actions.

Experience repeats

Each update moves an estimate toward a target; repeated visits make the table more stable.

Explore vs. exploit

Exploration gathers evidence. Exploitation chooses the highest estimate currently known.

Reading negative values: −1 is higher than −4. A policy still selects the numerically highest available value, even when every choice is costly.
