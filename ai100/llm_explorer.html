            How is the next word chosen?

            The model gives each possible next word a probability. You decide how to choose:

            Manual: Select Predict, then choose a word yourself.

            Sampling: Auto Generate chooses randomly using the probabilities. After “New Haven,” pizza has a 50% chance; sets and is each have 25%. Pizza is most likely, but not guaranteed.

            Greedy: Auto Generate always chooses the highest-probability word—here, pizza. The same starting words produce the same passage. Ties use the word that appears first in the training text.

            A different word changes the context for the next choice, so sampling can produce different passages. Neither method guarantees a meaningful sentence.

            Use the Auto Generate dropdown to choose a mode. Switching modes starts a fresh passage.

            Discovery: By repeatedly predicting the next word, a simple language model can generate text. But the result depends on the patterns it has observed, not an understanding of what the words mean.

            What we've discovered ? Next: Tokens
            • N-grams predict subsequent words using observed frequencies.
            • Repeated predictions can generate text.
            • More context makes exact sequence matching harder in limited data.
            • Unseen contexts and distant relationships remain challenging.
            • Statistical word prediction alone does not guarantee meaningful language.

            Next: Tokens. Modern language models process tokens, which are not necessarily complete words. How can reusable pieces help represent an enormous vocabulary?

            Tokenization alone does not resolve limited context. Modern models still face challenges with context, unfamiliar inputs, and meaning.

            A token may be a whole word, part of a word, or include spaces and punctuation.

            Discovery: A token isn't necessarily a word. Language models divide text into pieces based on their tokenizer's vocabulary.

            Discovery: Words and tokens are not always the same. A tokenizer can represent text using pieces that are smaller than words, complete words, or combinations that include spaces and punctuation.

            About the tokenizer

            One real tokenizer. Language models process sequences of tokens. This scene uses cl100k_base through js-tiktoken, a JavaScript version of OpenAI’s tiktoken library. Other tokenizers can split the same text differently.

            Exact text matters. Spaces, punctuation, capitalization, and line breaks can affect the split. The tiles preserve your input, and the word count is a simple whitespace-based comparison.

            Unicode and emoji. A token can contain only part of a character’s bytes. These tiles show “bytes”; striped highlights indicate a partially covered character.

            Runs in your browser. The tokenizer and vocabulary are bundled with this site. Your text is processed locally without sending it to a language-model API.

            Learn more: OpenAI tiktoken · js-tiktoken documentation (links open in a new tab)
